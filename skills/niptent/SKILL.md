# 素体のシェイプキーに合わせて衣装にシェイプキーを作る

素体の Nipple_On のように乳首を押し出すシェイプキーを入れると、素体にぴったり沿った衣装（ブラ・ビキニ・タイトなシャツ）は付いていけず、乳首が布を突き抜ける。
衣装に同じ名前のシェイプキーを作り、Modular Avatar の Blendshape Sync で素体の値に連動させれば、素体を切り替えた時に布も一緒に盛り上がる。

## 前提

- Unity 2022.3 のアバタープロジェクトに、MCP for Unity（`com.coplaydev.unity-mcp`）が入っていて、HTTP サーバーが動いている。
- Python 3（`scripts/run_cs.py` を動かす）。
- Modular Avatar は任意。入っていれば Blendshape Sync を足す。無ければ連動の設定だけ飛ばす。

## 実行のしかた

C# のスニペットは `scripts/run_cs.py` で Unity に送る。冒頭の `const` の値は `--set` で差し替える（ファイルは書き換えない）。

```bash
R=.claude/skills/niptent/scripts
python $R/run_cs.py $R/create_shape_from_body.cs --set "CLOTH=Avatar/Outfit/Bra"
```

- Unity が複数つながっている時は、`--instances` で一覧を出し、`--instance 名前@hash` で実行先を選ぶ。
- string の値はクォート不要。Windows のパスの `\` もそのまま書ける。bool / float は C# の書き方（`true`、`0.004f`）。
- Unity がコンパイル中・取り込み中だと失敗する。少し待ってから送り直す。

## 手順

1. **対象を確かめる。** 衣装のレンダラーのヒエラルキーのフルパス（アバターのルートから）と、素体のシェイプキー名を決める。
   シーンに同名のアバターや衣装が並んでいることがあるので、パスはルートから書く。非アクティブなオブジェクトでもよい。
   キーの名前はアバターによって違う。素体のキー一覧から、乳首を押し出すキーを探して `SHAPE` に渡す。
   素体は「同じアバターの中で `SHAPE` を持つ一番大きいレンダラー」を自動で選ぶ。素体が複数のメッシュに分かれている時は `BODY` で指定する。
2. **試運転する。** `create_shape_from_body.cs` を `CLOTH`（と必要なら `SHAPE`）を指定して実行する。既定は `APPLY = false` で、何も書き込まない。
   出力の読み方:

   | 行 | 意味 | 目安 |
   |---|---|---|
   | `before: SHAPE=0` | 作る前、素体のキーが 0 の時の突き抜け | 元の設計での食い込み。ここが基準 |
   | `before: SHAPE=100` | 作る前、素体のキーが 100 の時 | ここで突き抜けていなければ、作る必要は無い |
   | `existing:` | 衣装が元から持っている同名のキーを 100 にした時 | 衣装に同名のキーがある時だけ出る |
   | `pinch:` | 左右の乳首ごとに、布をつまんで出した量 D と、つまんだ範囲の頂点の数 | 素体のキーで乳首が動く量と同程度（数 mm）。0 なら、その側の布は乳首を覆っていない |
   | `pushed per pass` | つまんだ後、まだ肌に近すぎた所を押し出した頂点の数（回ごと）と、つまんだ形からの最大の追加量 | 最後が 0 に近ければ収束している。追加量が 2mm を大きく超えるなら、上からの画像で凹凸を見る |
   | `hull:` | 凸包まで持ち上げた頂点の数と最大の量 | 最大の量は `HULL_APEX`（1.5mm）前後。`skipped (no pinch)` は、つまむ必要が無かった側 |
   | `after: SHAPE=100` | 作った後 | `min mm` が `before: SHAPE=0` と同程度なら合格 |
   | `covered=` | 衣装が 6mm 以内にある肌の頂点の数 | 少なければ、その衣装はそもそも乳首を覆っていない |

   突き抜けは、肌の頂点ごとに最寄りの布の三角形を選び、その面の法線方向の距離で測る。
   衣装の縁の近くでは、覆っていない肌も「突き抜け」と数えることがある。合否は手順 4 の画像で決める。

   出力で次のどれかに当たったら、作る前に分岐する:

   | 出力 | すること |
   |---|---|
   | `existing:` の行があり、その突き抜けが `before: SHAPE=0` と同程度 | 配布元のキーで足りている。作り直さず、手順 3 を `--set SYNC_ONLY=true` で実行する（メッシュは変えず、値を素体に合わせて連動を足す） |
   | `before: SHAPE=100` の `penetrating` が `before: SHAPE=0` と同程度 | 作らなくても突き抜けない。ユーザーにそう伝え、布の上に乳首の出っ張りを見せたいかを聞く。見せたい時だけ作る（布が素体のキーの量だけ膨らむ） |
   | どちらでもない | 手順 3 で作る |

   止まる時:
   - `EreMorph ... has morphData`: 親に EreMorph の編集データがある。ビルド時に別のメッシュから作り直されるので、ここで差し替えても使われない。ユーザーに伝える。
   - `cloth has no vertex near the moved skin`: その衣装は、素体のキーが動かす場所の近くに無い。
3. **書き込む。** `--set APPLY=true` で実行する。スクリプトは次を行う。
   - 衣装のメッシュを複製してシェイプキーを足し、`.asset` に書き出す。既定の置き場所は、衣装のプレハブ（無ければメッシュ）と同じフォルダの `<メッシュ名>_<SHAPE>.asset`。`OUT` で変えられる。元の fbx は変えない。
   - 衣装のレンダラーを新しいメッシュに差し替える。既存のキーの値は引き継ぎ、新しいキーは素体の今の値にする。
   - Modular Avatar があれば Blendshape Sync を足す（コンポーネントが無ければ作る）。
   - 衣装にもう同名のキーがあると止まる。配布元のキーで足りるなら `--set SYNC_ONLY=true`、作り直すなら `--set OVERWRITE=true`。前回この手順で書き出したメッシュなら、同じアセットへ上書きして GUID を保つ。
   - 連動は省かない。素体と衣装の値を同じ数値に合わせただけでは、トグルやアニメーションで素体の値が変わった時に衣装が付いてこない。
4. **画像で確かめる。** `render_compare.cs` を `CLOTH` と `OUT_DIR`（`Assets` の外）を指定して実行し、出力の PNG を開いて見る。
   正面・近接・真横・上から（左右それぞれ）で、左が衣装のキー 0、右が 100 の画像が出る。素体のキーは 100 にして撮る。
   見るところ:
   - 右の画像で、乳首が布に覆われていること。
   - 上と真横の輪郭で、布が乳首の上に張ったテントになっていること。上から見た先は、角が 3 つほど並んだ凸な多角形になる。
     先が 2 つの角の間の平らな辺だけになっていたり、1 点だけ針のように尖っていたり、斜面から乳首の形のこぶが立ち上がっていたり（輪郭が凹む）しないこと。
   - テクスチャの付いたマテリアルで見る。素の灰色では形の良し悪しが分かりにくい。

   右の画像で乳首の先や赤い輪郭線が見えたら、`--set TARGET=0.0020f --set OVERWRITE=true` のように肌との距離を広げて作り直す。
   左の画像（衣装のキー 0）にも同じ場所の食い込みがあるなら、元の設計の食い込みなので直さなくてよい。
5. **保存する。** シーンを保存する（Unity で Ctrl+S、または `EditorSceneManager.SaveScene`）。

## 形の作り方

目指す形は、布が乳首の先に押されて張ったテント。乳首の形そのものを布に浮かせるのではない。
上から見ると、先は角が 3 つほど並んだ凸な多角形になる（先の平らな乳首に布を張った形）。
既定値は、配布元が作った Nipple_On を持つ衣装を上から見た輪郭をお手本にし、別のブラで同じカメラ・同じ倍率の画像を並べて、角の数・強さ・凹みが無いことを比べて決めた。ほかのブラ 2 着でも、輪郭が凸な多角形になることを確かめた。

`create_shape_from_body.cs` は次の順で形を作る。

0. **割る。** 素体のキーが動かす肌から 4mm 以内の布を、辺が 1mm 以下になるまで細かく割る（`SUBDIVIDE`、既定で有効。頂点数は元のメッシュから変わる）。

1. **つまむ。** 乳首の先の布をつまんで引き出したような形にする。布の各頂点を、その頂点の法線の向きに D × (1 − q²)²（q = 乳首の軸からの距離 / `PINCH_R`、既定 24mm）出す。
   D は、軸から 12mm 以内（`PINCH_CORE`）の布が、素体のキーを 100 にした肌から元の距離（乳首の近くでは `TARGET` の 1.2mm 以上）を保てる最小の値。
   素体の Nipple_On は乳首だけでなく周り 2cm ほどの肌も持ち上げる（12mm 先でも数 mm 動く）ので、布も広く滑らかに出す。
2. **足りない所を押し出す。** 布の頂点ごとに、キー 100 の肌との距離が足りなければ肌の法線の向きに押し出す。押し出しは点ごとに出るので、押し出した分だけを布の面に沿ってならし（`PUSH_SMOOTH`）、押し直す。
   最後に、乳首の側から布の三角形との距離を測り、近すぎる所を押し出す。布の頂点ごとの押し出しだけでは、頂点の間の面から乳首の先が抜ける。
3. **凸包まで持ち上げる。** 軸から 20mm 以内（`HULL_R`）の外を向いた布を、その範囲の頂点の凸包の面まで法線の向きに出す。
   このとき、軸から 4mm 以内（`HULL_TOP`）の布を 1.5mm（`HULL_APEX`）出した点も凸包に加える。先が平らな乳首に布を張ったテントの形になり、上から見て先に角が 3 つほど並ぶ。
   凸な形はどの向きから見ても輪郭が凸になるので、上や横から見て山の上に凹みや段が出ない。範囲の外側 4 割では持ち上げを 0 まで弱め、縁に段を作らない。
   つまむ必要が無かった側（布が乳首を覆っていない）は持ち上げない。凸包まで出すと、レースや浮いたカップの形が変わる。

| やり方 | 結果 |
|---|---|
| 最寄りの肌の動きを布に写し、ならしてから押し出す | 上から見て、斜面から乳首の形のこぶが立ち上がる（輪郭が凹む） |
| つまむ向きを乳首の向き 1 つにする | 乳首が外を向いている分だけ、胸の側面で布が途切れて段になる |
| つまむ範囲を、動く肌の近く（15mm）の布に限る | つまんだ形がその境で切れて段になる |
| つまむ量を、押し出した後の形に合わせて測り直す | 山が大きくなりすぎる |
| 凸包の先に 1 点だけを足す | 先が 1 点だけ尖り、隣の角が弱い |
| 先の上面を 0.5〜1.0mm 出す | 先の左の角が弱く、平らな上辺に見える |
| 割らずに作る（`SUBDIVIDE = false`） | 布の頂点が粗いままだと、上から見た先の上面が短く（お手本の半分）、左の角が弱く、角 2 つの形に見えた。割ると上面と斜辺の長さの比がお手本と同じ（1.03 / 1.05）になった |

- 同じ位置にある継ぎ目の頂点は 1 つにまとめて動かす。別々に動かすと継ぎ目が開く。
- ワールドでの移動量は、頂点ごとのスキン行列（Σ ウェイト × ボーンの localToWorld × バインドポーズ）の逆でメッシュ空間に直してからシェイプキーにする。
- 衣装の他のキー（胸の大きさのキーなど）は今の値のまま焼いた形で計算する。シェイプキーは足し算なので、移動量はそのまま使える。
- 近くの三角形は 4mm の格子で探す。総当たりだと、頂点の多い布で 30 秒（MCP の応答の上限）を超えた。
- 凸包は、6000 の向きの支持平面で外から近似する。

## つまずいた所

| 症状 | 原因 | 対処 |
|---|---|---|
| 乳首を覆っていないシャツでも `before: SHAPE=100` に突き抜けが出る | 最寄りの衣装の頂点が縁にあると、法線方向の距離が負になる | `covered` の数を見る。合否は画像で決める |
| 数値では突き抜けていないのに、真横の画像で乳首の先に赤い線が出る | 素体のトゥーンシェーダーの輪郭線は面より外に描かれる。布との距離が輪郭線の幅より狭いとはみ出す | `--set TARGET=0.0020f` のように肌との距離を広げて作り直す（既定 1.2mm） |
| 上から見た先の角が弱く、丸く見える | 先の上面を出す量が衣装に対して小さい | `HULL_APEX` を上げる。上げすぎると角が 36° を超えて尖る |

## 後始末

- 撮影用の一時オブジェクトと、非表示にしたレンダラーは `finally` で戻している。スクリプトが途中で落ちたら、`tmpcam` / `tmp_*` が残っていないか、アバターのレンダラーが無効のままになっていないかを確かめる。
  元のプレハブで無効になっているレンダラーもあるので、無効なものを見つけたら `PrefabUtility.GetCorrespondingObjectFromSource` で元の状態と比べる。
- コミットする前に `git status` を見る。衣装のフォルダが git 管理外だったり、シーンにほかの未コミットの変更が混ざっていたりする。混ぜてよいかをユーザーに聞く。
